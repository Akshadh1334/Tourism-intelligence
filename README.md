## 1. Idea in one paragraph

Hotels, travel agencies and tourism boards all suffer from the same problem: **demand is seasonal, shocks are unpredictable, and prices and marketing are set by habit rather than data.** This project builds a single analytics pipeline that (1) forecasts tourist demand for each destination with calibrated uncertainty, (2) detects abnormal months automatically, (3) turns the forecast into a **revenue-maximising hotel price plan**, (4) mines traveller reviews for what each destination is good or bad at, (5) groups destinations into behavioural segments, and (6) gives travellers an **explainable** recommendation and best-time-to-visit score.

| Who | What they get |
|---|---|
| Hotels | Month-by-month price multipliers (raise / hold / discount) with expected revenue impact |
| Tourism boards | 12-month demand forecast with 80% interval, anomaly alerts, destination segments |
| Travel agencies | Best time to visit and what to promote, per destination |
| Travellers | "Where should I go in December if I like beaches and nightlife, and why?" |

## 2. Dataset

No suitable public dataset covers monthly arrivals, weather, hotel prices and reviews together, so a **synthetic dataset** is generated by `src/data_gen.py` (seeded, fully reproducible). It covers **12 Indian destinations, Jan 2015 to Sep 2026 (1,692 monthly rows)** plus **7,200 review sentences**.

Built-in signals (so models have something real to find and can be scored honestly):

* yearly growth, destination-specific seasonality, festive-season uplift (Oct to Dec)
* weather (temperature, rainfall) turned into a comfort index that moves demand
* a COVID-19 style collapse and staged recovery (2020 to 2022)
* **48 injected one-off events** (disruptions and mega-events), kept in `data/injected_events.csv` as ground truth for the anomaly detector
* hotel ADR and occupancy generated with a **known price elasticity per destination**, so the elasticity estimator can be validated

Schema of `data/tourism_monthly.csv`: `date, place, arrivals, foreign_arrivals, avg_temp, rainfall_mm, comfort, is_festive, covid_factor, hotel_adr, hotel_occupancy, rooms`.

**Using real data:** replace the CSVs with real statistics (e.g. India Tourism Statistics from tourism.gov.in / data.gov.in, weather from IMD) using the same column names and run `python main.py`. Only the synthetic generators are specific to this dataset.

## 3. Data science concepts applied

| # | Module | Concepts | Why it is more than a basic model |
|---|---|---|---|
| 1 | `anomaly.py` | STL decomposition, robust z-score (median/MAD), Isolation Forest, voting | **Weather-aware:** the weather effect and the COVID regime are removed *before* detection, so a rainy month or the pandemic is not mistaken for a point anomaly |
| 2 | `forecasting.py` | Holt-Winters, **global** gradient boosting on detrended log-demand, inverse-error ensembling, split-conformal-style intervals, rolling-origin backtest | Training data is **anomaly-cleaned** first; ensemble weights and interval width are learned on a validation year, metrics are reported on an untouched test year (no leakage) |
| 3 | `pricing.py` | Log-log regression for **price elasticity**, constrained revenue optimisation | Turns a forecast into a *decision*: raise prices where capacity binds, discount where demand is price-sensitive |
| 4 | `sentiment.py` | TF-IDF + logistic regression, rule-based aspect tagging, aggregation | Aspect-level scores (food, hotel, safety, ...) rather than one star rating |
| 5 | `segmentation.py` | Feature engineering, standardisation, K-Means with silhouette-chosen k, PCA | Destinations are described by *behaviour* (seasonality, COVID resilience, price sensitivity, ...) and auto-named |
| 6 | `recommender.py` | Hybrid content + context scoring, cosine similarity, explainability | Combines interests, month-specific weather, forecast crowding and review sentiment, and returns *why* |

## 4. Results (from `python main.py`, seed 42)

**Forecasting** (test = last 12 months, never used for fitting or tuning; 12 destinations x 12 months):

| Model | MAPE (test) |
|---|---|
| Seasonal naive (baseline) | 8.86% |
| Holt-Winters | 7.33% |
| Trend + Gradient Boosting (global) | 7.14% |
| **Ensemble** | **6.82%** |

The 80% prediction interval covered **87.5%** of test months (slightly conservative). Test months include injected shocks and unknown future weather, so this error is realistic rather than optimistic.

**Anomaly detection** (against 48 injected events, COVID window excluded):

| Detector | Precision | Recall | F1 |
|---|---|---|---|
| STL robust z-score | 0.86 | 1.00 | 0.92 |
| Isolation Forest | 0.67 | 1.00 | 0.80 |
| **Voting combination** | **0.89** | **1.00** | **0.94** |

**Pricing:** the elasticity estimator recovered the true per-destination elasticities with a mean absolute error of **0.034**. The optimised plan gives a **modelled revenue uplift of about 5.4%** versus flat pricing across the next 12 months.

**Reviews:** sentiment classifier accuracy 93.7% (F1 0.96) on held-out sentences; aspect tagging covers 100% of sentences.

**Segmentation:** k = 3 chosen by silhouette (0.23).

Figures are in `results/`: `forecast_grid.png`, `anomalies.png`, `model_comparison.png`, `pricing.png`, `segments.png`, `aspect_sentiment.png`.

## 5. How to run

```bash
git clone <your-repo-url> && cd tourism-intelligence
pip install -r requirements.txt

python main.py --regen          # full pipeline, writes data/ and results/
python explore.py Goa           # forecast, best time, price plan, reviews, similar places
python explore.py --recommend beach=9 nightlife=7 budget=5 --month 12
```

Runtime is roughly 10 seconds on a laptop.

## 7. Limitations (please read)

* **All data is synthetic.** Accuracy numbers show the pipeline works and is evaluated without leakage; they are **not** claims about real Indian tourism. Real data will be noisier.
* Because the generator is simple, some models can recover its structure more easily than they could recover reality. The sentiment accuracy in particular is optimistic (template sentences).
* The **5.4% pricing uplift is model-based**, computed from the same elasticity model that chooses the prices. It would need an A/B test with real hotels to confirm.
* Anomaly thresholds were calibrated on the synthetic data; re-tune them on real series. The voting combination and the STL detector perform similarly here, because STL already does most of the work once weather and COVID are removed.
* Growth is the same for every destination by construction, so the "fast growth" tag in the segments is partly noise on this dataset.
* Future weather is assumed to equal the historical average for each month; a weather forecast feed would improve short-horizon accuracy.
